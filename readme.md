# Автотесты для API (Практикум SDET)

Этот репозиторий содержит автоматизированные тесты для REST API в рамках практикума SDET. Проект демонстрирует использование Python для тестирования API, включая работу с HTTP-запросами, валидацию моделей данных, генерацию отчетов и запуск в CI/CD.

## 🚀 Технологический стек

-   **Python 3.10+**
-   **Pytest:** основной фреймворк для написания и запуска тестов.
-   **Requests:** HTTP-клиент для взаимодействия с API.
-   **Pydantic:** валидация моделей данных (DTO) для запросов и ответов.
-   **Allure Report:** фреймворк для создания информативных и наглядных отчетов о тестировании.
-   **pytest-xdist:** плагин для параллельного запуска тестов.
-   **python-dotenv:** управление переменными окружения (например, хостом API).

## 🛠️ Установка и настройка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/l-calax-l/sdet_practicum_api.git
    cd sdet_practicum_api
    ```

2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    # Для Windows
    python -m venv venv
    .\venv\Scripts\activate

    # Для macOS / Linux
    python3 -m venv venv
    source venv/bin/activate
    ```

3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

4.  **Настройте переменные окружения:**
    Скопируйте файл `.env.example` в новый файл с именем `.env` и при необходимости измените значение `API_HOST`.
    ```bash
    # Для Windows
    copy .env.example .env

    # Для macOS / Linux
    cp .env.example .env
    ```

## ▶️ Запуск тестов

### Простой запуск

Выполняет все тесты в одном потоке.
```bash
pytest
```

### Параллельный запуск

Запускает тесты в несколько потоков (количество определяется автоматически), что значительно ускоряет выполнение.
```bash
pytest -n auto
```

### Запуск с генерацией Allure-отчета

1.  **Выполните тесты и соберите результаты:**
    ```bash
    pytest --alluredir=allure-results -n auto
    ```

2.  **Сгенерируйте и откройте HTML-отчет:**
    (Требуется установленный [Allure Commandline](https://docs.qameta.io/allure/#_installing_a_commandline))
    ```bash
    allure serve allure-results
    ```
## 📝 Известные проблемы

На данный момент в тестируемом API существует известный баг, подтвержденный ментором:

*   **Проблема:** Эндпоинт `GET /get/{id}` возвращает статус-код `500 Internal Server Error` при обращении к несуществующему (в том числе удаленному) `id`.
*   **Ожидаемое поведение:** Должен возвращаться статус-код `404 Not Found`.

Позитивные автотесты в этом проекте адаптированы для корректной работы в условиях этого бага. В частности, тест на удаление сущности (`TC-04`) проверяет, что после удаления GET-запрос возвращает любой код ошибки `>= 400`, что делает тест стабильным.
## ⚙️ CI/CD

Проект настроен для автоматического запуска тестов с помощью GitHub Actions. Пайплайн запускается при каждом `push` в ветки `main` или `develop`, а также при создании `Pull Request` в `main`.
